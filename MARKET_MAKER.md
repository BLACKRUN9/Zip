# Market-maker console, bots and accounts (SIMULATED)

Everything here runs against NEXORA's **simulated** exchange with simulated funds. Bots can only call the in-process `DemoExchange`; there is no connector to any external venue, and the engines refuse to run unless `DEMO_MODE=true`.

## Accounts and roles
| Account | Role | Can do |
|---|---|---|
| `user1`, `user2` | USER | trade, wallet |
| `mm` | MM | trade, wallet, view/control/configure **its own** bots |
| `mm2` | MM | same; used as the counterparty ("sell account") of volume bots |
| `admin` | ADMIN | everything: all bots, approve/reject simulated transfers, admin dashboard |

Roles come from the server-side directory, never from the browser. There are no passwords yet: until Milestone 2 (real auth) the server operator picks the acting account with `NEXORA_DEV_ACTOR` in `.env` and restarts `npm run dev`. That switch is ignored in production builds and when `DEMO_MODE` is not `true`.
An MM may control a bot only if **every** account it uses is the MM's own, so cross-account volume bots are ADMIN-only. An MM can still *see* a bot that uses its account.

## Order bots (one bot = one config; clone for more)
Fields (as in your CSV): `account_id, price_source, price_decimal, quantity_decimal, random_min_quantity, random_max_quantity, order_count, expire_time, transaction_type, split_order_mode, split_range, buy_/sell_trailing_*_percentage, buy_max_price_limit, sell_min_price_limit, jitter_timing_pct, jitter_price_pct`.
Run 3 buy bots + 3 sell bots by cloning and changing `transaction_type` (`buy_only` / `sell_only` / `both`) and the other fields.

### How the engine interprets them (ASSUMPTIONS — please confirm or correct)
- `account_id`: an external label. It must be mapped explicitly to a NEXORA account (`ACCT1=mm`); the target must hold the MM role.
- `price_source`: `reference` = the market's reference price (editable in the console); `last` = last trade; `mid` = best bid/ask midpoint. Anything else is rejected.
- `split_range`: one entry per level. Level *i* is placed at `reference × (1 ± Σ split[0..i] / 100)` (sell above, buy below): first entry = distance of the first level, the rest = steps between levels.
- `jitter_price_pct`: each level's offset is randomised by ± this percent **of the offset** (not of the price).
- `jitter_timing_pct`: each order's lifetime is randomised by ± this percent of `expire_time`.
- `expire_time`: seconds before an unfilled order is cancelled and re-quoted. Filled orders are re-quoted on the next tick.
- `sell_min_price_limit` / `buy_max_price_limit`: a level whose price would break the limit is skipped (logged), not clamped.
- `price_decimal` / `quantity_decimal`: rounding of generated prices (half-up) and quantities (multiples of 10^-n).
- `split_order_mode`: only `manual` is supported. `*_trailing_*`: must be `None` (not supported yet; any value is an error).
- Quantities and limits are in the market's own units (base for quantity, quote for prices).

## Volume bots (SYNTHETIC volume)
Fields: `account_id, volume_price_decimal, volume_quantity_decimal, volume_random_min_quantity, volume_random_max_quantity, min_delay, max_delay, min_difference, max_difference, priority, max_limit_price, min_limit_price, vol_idr_stop_target, vol_idr_start_threshold, volume_sell_account_id`.

Every trade a volume bot causes is **tagged SYNTHETIC**: the chart shows "Includes SIMULATED bot volume" and trade lists mark it. Both accounts must be MM accounts, so ordinary users are never touched. This exists to make a *demo* look alive and to test strategy logic; synthetic volume must never be presented as organic market activity, and running such a bot on a real venue is wash trading, which is prohibited. That is outside this project.

### Interpretation (ASSUMPTIONS — please confirm)
- `volume_sell_account_id` set → **cross mode**: `account_id` buys from that account; `priority` (`random`/`buy`/`sell`) chooses which leg rests first. `None` → **book mode**: `account_id` takes liquidity from the book (market order); `priority` chooses the direction.
- `min_difference`/`max_difference`: percent offset from the base price (random sign) for the cross price. Ignored in book mode.
- `min_delay`/`max_delay`: seconds between volume trades (the scheduler ticks every 0.5 s).
- `min_limit_price`/`max_limit_price`: trades only happen inside this band.
- `vol_idr_start_threshold`: only generate while the trailing-24h quote volume is below it. `vol_idr_stop_target`: auto-stop when volume generated by this bot reaches it. Despite the `idr` name these are in the market's **quote currency**.

## Using the console
`/mm` (roles MM and ADMIN): import a CSV (market + account mapping; anything invalid imports nothing), start/stop, clone, edit fields of a stopped bot, set reference prices, watch live orders and the activity log. Changes are audited (visible in the admin dashboard). Bots start STOPPED after import.
Autostart (operator level): `MM_AUTOSTART=true` loads `config/mm.config.json` → `config/mm-strategies.csv` and starts every bot. The shipped CSV is your file with the account id anonymised (`ACCT1`).

## Limits
In-memory only (resets on restart), one process, polling UI, no persistence of bot edits.
